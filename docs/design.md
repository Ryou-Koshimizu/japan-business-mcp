# 設計メモ

## 全体の形

```
cmd/japan-business-mcp   実行ファイル。-http を付けると Streamable HTTP、付けないと標準入出力（stdio）
cmd/wasm                 同じサーバーを WebAssembly にして、ブラウザの中で動かす（遊び場）
internal/server          MCP の道具12・資料3＋テンプレート1・依頼文3 を登録する。どの通り道からも同じ *mcp.Server
internal/holiday         祝日・振替休日・国民の休日・会社カレンダー・営業日
internal/payterm         締め日と支払日（休みなら前営業日・翌営業日）
internal/corpnum         法人番号・登録番号の検査用数字
internal/ctax            消費税（税率ごとに1回の端数処理）・適格請求書の記載事項
internal/withholding     報酬・料金の源泉徴収
internal/stamp           領収書の印紙税
internal/wareki          和暦⇔西暦
internal/textnorm        表記ゆれ・住所の正規化
internal/jpdate          時刻を持たない日付の型
internal/testcases       道具の呼び出し例と正解（ゴールデン）。サーバーの試験・実行ファイルの試験・遊び場の例で共有
scripts/realworld        実機試験（公的データとの突き合わせ）
e2e/                     遊び場の実ブラウザ試験
```

計算の部品（internal/holiday など）は MCP を知らない。MCP の層（internal/server）は、引数の読み取り・既定値・説明文・JSON の形だけを受け持つ。部品を単体で試験でき、MCP の SDK の版が上がっても計算に手が入らない。

## 公式 Go SDK の使い方

- `github.com/modelcontextprotocol/go-sdk` v1.8.0。`mcp.AddTool` に型付きの関数を渡し、入出力の JSON Schema を Go の型から作る。
- 日付の型 `jpdate.Date` は、`jsonschema.ForOptions.TypeSchemas` で `{"type":"string","format":"date"}` として出す（SDK は出力をスキーマで検証するため、型と JSON の形を一致させる）。
- 道具の結果は `structuredContent`（構造化）と、同じ JSON の `text` の両方で返る。構造化を読まないクライアントでも同じ中身を受け取れる。
- 道具にはすべて `readOnlyHint` と `idempotentHint` を付け、`openWorldHint=false`（外部に出ない）とする。
- HTTP は `mcp.NewStreamableHTTPHandler`。`http.NewCrossOriginProtection` で他のサイトからの呼び出しを断り、`JBIZ_HTTP_TOKEN` を設定すると `Authorization: Bearer` を確かめる。SDK の既定で、localhost に来た別ホスト名の要求（DNS リバインディング）も断る。

## 祝日

表を持たず、法律の規則から計算する。

| 規則 | 実装 |
| --- | --- |
| 固定日の祝日と、制定・改正の年 | `nationalHolidays`（建国記念の日は1967年から、山の日は2016年から など） |
| ハッピーマンデー | 成人の日・体育の日（2000年〜）、海の日・敬老の日（2003年〜） |
| 春分の日・秋分の日 | 近似式 `int(20.8431 + 0.242194(Y−1980) − int((Y−1980)/4))`（年代ごとに係数を変える）。1980年より前は `int((Y−1983)/4)` を0方向に切り捨てる |
| 振替休日 | 1973-04-12 施行。2007年からは「その後で最も近い祝日でない日」 |
| 国民の休日 | 1985-12-27 施行。前後が祝日の日。2007年より前は日曜を除く |
| 特措法・皇室の慶弔 | 2020・2021年の移動、1959・1989・1990・1993・2019年の休日。2019-05-01 は祝日とみなすため、前後が国民の休日になる |

春分・秋分は、前年2月の官報（暦要項）で確定する。公表済みの年（2027年まで）を `LastGazettedYear` に持ち、それより後は「計算式による見込み」として `is_estimate` を返す。

試験では、内閣府が公開している CSV（1955〜2027年・1,067日）を、取得したままのバイト列（Shift_JIS・SHA-256 を記録）で置き、規則の計算と1日ずつ突き合わせる。表記の違い（内閣府は振替休日と国民の休日をどちらも「休日」と書く など）は、試験の側で写像する。

## 営業日と会社カレンダー

- 判定の優先順：出勤日の指定 ＞ 祝日・休日 ＞ 特定日の会社の休み ＞ 毎年の会社の休み ＞ 土日。
- 毎年の休みは `[13][32]bool` の集合、特定日は map。判定は O(1)、祝日の索引も年ごとの map で O(1)。
- 会社の休みは範囲（`12-29..01-03`、`2026-08-13..2026-08-16`）で書ける。範囲を展開した後の合計で 2,000 日を上限にし、道具の引数で暦を渡したときは、たどる日数の上限も約20年に下げる（重い入力でサーバーの資源を使い切らないため）。
- 道具の中で予期しない panic が起きても、サーバーは落とさず MCP のエラー応答にする（`addTool` の recover）。

## 検査用数字

`9 − (Σ Pn×Qn mod 9)`（Qn は奇数桁1・偶数桁2）。9 で割った余りを使うため、1桁の書き間違いは「0と9の入れ替え」を除いてすべて見つかり、0↔9 は式の性質として区別できない。この性質そのものを試験している（`TestSingleDigitErrorDetection`）。

適格請求書発行事業者の登録番号は、個人事業者の番号も同じ検査用数字の付け方で発番されている。実機試験で、国税庁の公開データ（個人・人格のない社団等・法人）の番号 331,285 件がすべて通ることを確かめた。

## 消費税

- 税率ごとに金額を合計し、税額の端数処理を1回だけ行う（消費税法施行令第70条の10）。品目ごとに端数処理した場合の税額も計算し、差を示す。
- 金額は円の整数、計算は `math/big` の整数演算（浮動小数の誤差を入れない）。値引きの行（負の金額）は絶対値で端数処理して符号を戻す。
- 記載事項の確認では、書かれた税額が「税率ごとに1回の端数処理（切り捨て・四捨五入・切り上げのどれか）」と一致するかを見て、品目ごとの端数処理の合計と一致する場合はそれと分かる言葉で指摘する。

## 源泉徴収

- 100万円以下 10.21%、超える部分 20.42%（＋102,100円）。司法書士・土地家屋調査士・海事代理士は 1万円を引いて 10.21%。1円未満は切り捨て。
- 復興特別所得税は 2013-01-01〜2037-12-31 の支払いに加わる。支払日を受け取り、2038年以降は 10%／20% で計算する。
- 手取りからの逆算は、手取りが報酬額に対して単調に増えることを使った二分探索。同じ手取りになる報酬額が2つあるとき（例：99,999円 と 100,000円 はどちらも手取り 89,790円）は小さいほうを返す。

## 和暦

- 改元の日で区切る（明治 1868-10-23、大正 1912-07-30、昭和 1926-12-25、平成 1989-01-08、令和 2019-05-01）。
- 日付の変換は太陽暦を採用した 1873-01-01（明治6年1月1日）から。年だけの変換は明治元年（1868年）から。
- 「令和元年」「R8.10.20」「令和八年十月二十日」「H31/4/30」を読む。期間の外の日付（平成31年5月1日）は、正しい元号（令和元年5月1日）を添えてエラーにする。
- 1873〜2150年の全日（101,537日）で、西暦→和暦→西暦が元に戻ることを試験している。

## 表記ゆれ

- NFKC（全角英数字→半角、半角カナ→全角、①→1 など）、数字・英字に挟まれた長音やダッシュ→「-」、空白のまとめ、ひらがな⇔カタカナ。
- 住所：丁目・番地・番・号→ハイフン、漢数字（丁目などの直前だけ）→算用数字、郵便番号→「〒123-4567」。「一番町」「国道一号線」「301号室」「5番館」は、後ろの文字を見て変えない。英字の部屋番号や次の数字とつながらないよう、必要なところに空白を残す。
- どの処理も2回かけて結果が変わらない（冪等）ことをファズで確かめ、さらに鳥取県の全法人の所在地 20,258 件で、冪等・全角が残らない・数字の並びが変わらないことを確かめた。

## 遊び場（WebAssembly）

- `cmd/wasm` は `internal/server.New` をそのまま使い、SDK の `NewInMemoryTransports` でつなぐ。ブラウザからは JSON-RPC の文字列をそのまま渡し、返事の文字列を受け取る。画面に流れる JSON は、実際にサーバーが返した電文。
- 15MB の WebAssembly を gzip（3.6MB）にして置き、ブラウザの `DecompressionStream` で展開する。配信先が wasm を圧縮しなくても転送量は 3.6MB。
- 質感は CRT：走査線と画面の縁の暗がり（湾曲）を固定の層で重ね、文字は `text-shadow` でにじませる。起動の画面の進み具合は実際の受信バイト数。動きを減らす設定では、起動の画面・打ち込み・ちらつきを止める。
- ヘッダーは 80px、ヒーローは `calc(100svh − 80px)`（古いブラウザ向けに `100vh` も）。見出しは `min(12.2cqi, 10.5svh)` で幅と高さの両方に合わせて縮み、背の低い横向きの画面では補足の文と飾りを畳む。

## 試験の層

| 層 | 中身 |
| --- | --- |
| 単体（表駆動） | 各部品の境界値・改正の年・エラー |
| ファズ | 検査用数字・正規化（冪等）・和暦・支払期日・月の計算・会社カレンダーの展開 |
| ゴールデン | 24の呼び出し例の構造化出力を `internal/testcases/golden` に固定。サーバー・実行ファイル（stdio・HTTP）・遊び場の画面で同じ正解を使う |
| MCP 結合 | 実際に `go build` した実行ファイルを、SDK のクライアントで stdio（CommandTransport）と Streamable HTTP の両方から叩く |
| 実機 | `scripts/realworld`：内閣府・国税庁の公開データを取得し、配る実行ファイルを stdio と HTTP から 71,360 回ずつ呼んで照合 |
| 実ブラウザ | Playwright：Chromium と WebKit、25の画面の大きさ、全例の返事とゴールデンの一致、axe（WCAG 2.1 A/AA） |
